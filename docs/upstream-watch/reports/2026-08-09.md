## 新吸收：视频生成准备度门禁

Jellyfish 的镜头准备度服务强调“先回答当前镜头能不能生成、还差什么”，检查信息确认、镜头时长、提示词、参考帧、模型、供应商和活动任务。Toonflow 没有复制其 Python/FastAPI/SQLAlchemy 源码，而是结合自身 Vue、TypeScript、SQLite、可编程供应商和持久任务架构独立实现。

Toonflow 新门禁覆盖：

- 项目、剧本和镜头轨道归属；
- 视频提示词和正时长；
- 当前模式要求的分镜/资产参考是否真实存在且属于当前项目；
- 视频模型存在、供应商启用、必填输入完整；
- 模式及“时长 + 分辨率”组合是否被模型声明支持；
- 同镜头是否已有非终态视频任务。

单条和批量前端会在确认生成前调用只读检查并汇总失败原因；服务端入队在预算预留和供应商提交前再次执行，避免旧客户端或直接接口绕过。检查不调用模型、不读取或回传密钥，也不产生费用。Toonflow 落地提交：`80c728d4`。

## 新吸收：已确认动作拍点

参考 Jellyfish 的动作拍点设计，并结合已登记的 drama-skills 连续性约束方向，Toonflow 独立建立了“候选生成 → 持久化 → 人工编辑确认 → 提示词编译”的完整闭环，而不是只追加一段模型提示词：

- `o_storyboard` 保存动作拍点 JSON 和人工确认状态，迁移可重复执行；旧记录默认未确认。
- 生产 Agent 每个写入单位生成 2–4 条有序动作/状态变化，只能取自现有分镜内容，写入后始终处于待确认。
- 分镜卡显示拍点数量和状态；用户可逐行编辑，只有明确勾选人工确认后才能生效。
- 单条/批量视频提示词只读取已确认拍点，并确定性编译为 setup / trigger / peak / aftermath 等阶段；未确认和旧数据完全走原 `videoDesc` 路径。
- 四套运行时视频模型提示词和后备系统提示词契约均要求按顺序消费全部拍点，不得编造原分镜以外的剧情。

本能力使用 Toonflow 自身 Vue、Express、SQLite 和提示词路由实现；没有引入 Jellyfish Python 服务为运行依赖。

## 新吸收：视频海报帧

参考 huobao-drama `99e66809` / `a1b8220f` 的产品行为，在 Toonflow 独立实现视频海报缓存：视频保存成功后后台提取 0.5 秒 JPEG，短片回退 0 秒；同文件去重、全局最多两个任务、partial 原子落盘。工作台三个视频查询入口返回 `posterSrc`，历史视频缺海报时后台补齐，前端仍保留浏览器首帧回退。FFmpeg 不可用或提取失败不影响视频任务成功。
